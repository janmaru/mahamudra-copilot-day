# 2 · Glossary

> Each term is defined **once and only once**. Other chapters link back here. Synonyms are not allowed: if a second name for the same thing is needed, there is a modeling error.

## Knowledge Context (or, shortened, **Context**)

A named aggregate that contains zero or more *Snippets* related to a theme. Identified by an `Id` (GUID generated by the system). Has a free-form `Name`, a free-form `Description`, and keeps the `CreatedAt` and `UpdatedAt` timestamps.

Example Contexts: *"Developer onboarding"*, *"Tier-1 support FAQ"*, *"Copilot configuration samples"*.

## Snippet

A single fragment of knowledge held within a Context. It has:

- `Id` (GUID);
- free-form `Title`;
- free-form `Content`, of any length;
- `Tags`, a (possibly empty) array of short strings;
- `CreatedAt`.

A Snippet exists only inside the Context that contains it: there is no *global* Snippet, and it is not shareable across Contexts.

## Tag

A short string attached to a Snippet for informal categorization. Tags are **opaque** to the system: no closed taxonomy, no validation, no normalization (`Setup` and `setup` are stored as distinct tags as received, but search treats them case-insensitively).

## Search

Read operation that returns Snippets of a Context whose `Title`, `Content`, or one of the `Tags` contains the given *query*, in a case-insensitive way.

A search with an empty or absent query is equivalent to "all snippets of the Context".

## Write operation

Any request that changes system state: `POST`, `PUT`, `DELETE`. Write operations refresh the `UpdatedAt` of the involved Context.

## Read operation

Any `GET`. Does not alter state, does not refresh timestamps.
